# /fast-flow — adaptive fast lane

## Problem

The feature / debug / polish flows optimise for correctness: 3-5 explorer
fan-out, 2-3 grill rounds, ground-truth gate, chunk manifests, dual reviewers.
Measured all-lane baseline: median dispatch 8.8 min, p90 22.8 min
(`skills/charles-flow/SKILL.md:53-56`); a feature run chains several of them.
Small and medium asks do not need that much machinery.

## Design

`/charlesdr-dev-loop:fast-flow <ask>` keeps the skeleton (plan file → grill →
implement → isolated review → green → sign-off → close) and fixes the cost:

- **one** luna explore lane, not a fleet
- **exactly two** grill rounds: round 1 is the `grill-rounds` codex adversary,
  round 2 is one batched message to the user; there is no round 3
- **one** serial luna implementer in a `treehouse` worktree
- **one** review, default engine (sol @ medium)
- debug-loop cap of **2** cycles

Every luna dispatch runs at the luna default — `--effort max`
(`scripts/codex-run.sh:143`) with codex `fast_mode` on unless the weekly
quota probe finds under 20% remaining (`weekly_quota_fast_mode`,
`scripts/codex-run.sh:706`) or the engine is overridden by `/engine` or
`CHARLES_ENGINE` (`scripts/codex-run.sh:201-222`). The command therefore
never passes `--fast`, which would lower effort to `high`
(`scripts/codex-run.sh:174`).

One dispatcher change: `CHARLES_FAST_MODE=1` in the environment makes
`weekly_quota_fast_mode` return `--enable` without probing, so fast-flow keeps
`fast_mode` on even under the 20% weekly gate. Terra keeps `--disable`
(`scripts/codex-run.sh:776`). Every `codex-run` call in the command is
prefixed `CHARLES_FAST_MODE=1`; the normal flows never set it, so their gate
is unchanged.

Three things are called "fast" and the command file must keep them apart:
the flow key `fast` in `scripts/flow.json`, the `--fast` dispatcher flag
(effort `high`; never used here), and codex `fast_mode` (a provider option
the dispatcher already manages).

Adaptive: step 1 classifies the ask as `debug` (broken, has a symptom or
repro) or `build` (feature, polish, refactor). Classification changes only the
explore brief and plan shape; the pipeline after that is fixed.

Skipped by design, and the command file says so: the brainstorming step, the
explorer fan-out, grill round 3 (a deliberate departure from
`skills/grill-rounds/SKILL.md:97-102`), the `.chunks.json` manifest and
parallel path, and the second reviewer. Prior art is one repo grep plus one
knowledge-base query when a KG tool is configured. Asks that are UI/UX, that
clearly need 2+ parallel chunks, that edit the flow machinery, or that are
security-, state- or concurrency-sensitive (where two reviewers are the
rule, `skills/charles-flow/SKILL.md:260-275`) are routed to `/ui`,
`/feature` or `/debug` instead — at classify time and again once the plan
exists.

## The pipeline `commands/fast-flow.md` must describe

Gate: no `.charles.toml` → stop and offer `/charlesdr-dev-loop:init`. An
already-open run → stop and offer `/charlesdr-dev-loop:resolve`.

Any lane failure, `verify-receipt.sh` exit other than 0, or review exit 3
(empty diff) records a `FAILED` item and stops with a report. Never fall back
to inline work. Record `run-state.sh phase` at every step boundary.

1. **Classify + baseline.** One line: `debug`, `build`, or `route-out`
   (UI/UX → `/ui`; 2+ chunks, flow machinery, or security/state/concurrency
   → `/feature` or `/debug`). Then `green.sh "$(pwd)"`; red baseline → stop
   and offer `/debug`.
2. **Explore — one lane.** One Bash call with `run_in_background: true`:
   `CHARLES_FAST_MODE=1 codex-run --lane explore --dir "$(pwd)" --timeout 2700 "<brief>"`. Never
   pass `--fast` or `--effort`. Debug brief: repro plus "cause with
   `file:line` evidence, no patch". Build brief: prior art in this repo,
   integration points, files in scope, one competing design. Then
   `verify-receipt.sh "$(pwd)" --lane explore --since 1800`. For `debug`,
   confirm the cause against source yourself before step 3.
3. **Plan.** `docs/specs/YYYY-MM-DD-<topic>.md`, at most six checkable
   `- [ ] **R#**` requirements, files in scope, green command. One
   knowledge-base prior-art query if a KG tool is configured. Open the run:
   `run-state.sh init "$(pwd)" fast "<goal>" --spec <plan>`. No manifest. If
   the plan turns out to need 2+ chunks, stop and route to `/feature`.
4. **Grill round 1 — codex adversary.** The `grill-rounds` round-1 dispatch
   exactly (`--lane explore`, read-only, its attack prompt, background,
   `CHARLES_FAST_MODE=1`).
   Answer every item from source; amend the plan in place.
5. **Grill round 2 — one message.** Record survivors as `BLOCKED-HUMAN`, then
   one batched `❓ / ➡️` message. Zero survivors → say so and continue.
   Otherwise wait: nothing proceeds while an item is unanswered. No round 3:
   answers that reshape the plan amend it and proceed, noted under
   `Accepted risks`. Append the full `grill-rounds` verdict block with
   `- Rounds: 2`.
6. **Implement — one lane in a worktree.** `WT="$(treehouse get ...)"` or,
   without treehouse, `git worktree add .claude/worktrees/fast-<ts> HEAD`.
   One Bash call with `run_in_background: true`:
   `CHARLES_FAST_MODE=1 codex-run --lane implement --dir "$WT" --plan "$(pwd)/<plan>" --req <all R IDs> --timeout 2700 "<brief naming ponytail>"`
   (no `--run`: the worktree has no run directory). Then
   `verify-receipt.sh "$WT" --lane implement --since 2700`, append
   `"$WT/.charles/dispatches.jsonl"` to `"$(pwd)/.charles/dispatches.jsonl"`,
   and merge: `git -C "$WT" add -A && git -C "$WT" diff --cached HEAD | git apply --index`
   in the root. Return the worktree.
7. **Review — one pass.** `CHARLES_FAST_MODE=1 codex-run --lane review --dir "$(pwd)" --plan <plan> --timeout 540 "<focus>"`
   with the outer Bash `timeout: 600`; background `--timeout 2700` only for a
   heavy diff. Exit 3 → `FAILED`. `GAPS FOUND` → one implement cycle. Verify
   every finding against source before acting.
8. **Verify, sign off, close.** `green.sh`; cap 2 implement/review/green
   cycles, then a `FAILED` item and stop. `## Sign-off` with pasted output.
   `run-state.sh close "$(pwd)" "<outcome>" --spec <plan>`.
