# Lean loop (2.49.0)

Charles, 2026-10-26: "can we make the loop more efficient? I think its too time consuming, we need to account all the llm improvements you know. maybe things are just too hand holdy".

Evidence (14-day audit, 2026-10-12..26, 992 sessions, 338 lane runs, 43 flow runs):
the edit/subagent gates have been bypassed globally since 2026-09-22 and asked 0 times;
92 runs are open, 90 idle for more than 14 days, and the Stop hook warned 1,920 times (1,714 about one dead run);
30 dispatches were refused by the plugin's own checks; 21 of 33 plans ended on GAPS FOUND after up to 7 review rounds;
14 of 43 runs needed `--force` to close; 30 of 43 specs waived the grill; fallback to deepseek fired 0 times
while 5 grok lanes died together on a 402. The models are good enough now that the ceremony costs more than it catches.

Scope: make the default loop plan → implement → one review → green → close, and remove machinery that
blocks good work. Keep the isolated reviewer, run state, receipts and the sign-off gate.

## Requirements

### Code lane (scripts/, hooks/, .charles.toml, scripts/selftest.sh, scripts/doctor.sh, scripts/init-repo.sh)

- [ ] **R1** — The inline-edit and subagent gates are gone: `hooks/route-to-codex.sh`, `hooks/route-subagents.sh` and `hooks/mark-inline-ok.sh` are deleted, their entries are removed from `hooks/hooks.json` (and its description updated), their selftest sections are removed, and no script still reads `inline_lines`, `inline_files`, `.charles/touched`, `.charles/inline-ok` or `.charles/pending-ask` (remove those keys from `.charles.toml` and from whatever `init-repo.sh` seeds). `claude-lane-dispatch.sh`, `claude-lane-receipt.sh` and `claude-review-box.sh` stay.
- [ ] **R2** — `hooks/link-dispatcher.sh` (SessionStart) abandons every open run in the current repo whose `RUN.md` has not changed for `CHARLES_STALE_DAYS` days (default 7) through `run-state.sh abandon` with reason `stale: no activity for <N> days`, prints one line `charlesdr-dev-loop: auto-abandoned <n> stale run(s)` when it did, and its open-run line counts only what is left. It no longer prints the ABANDONED-runs line. A selftest proves an 8-day-old run is abandoned and a fresh one is left open.
- [ ] **R3** — `hooks/warn-open-runs.sh` (Stop) only reports FAILED items from an open run whose `RUN.md` changed in the last 24 hours, and never prints the ABANDONED line. Selftest proves a 2-day-old run with a FAILED item is silent and a fresh one still warns.
- [ ] **R4** — `scripts/codex-run.sh`: with several open runs and no `--run`/`CHARLES_RUN`, open runs whose `RUN.md` is older than 24 hours are ignored; if `--plan` is given, the run whose spec matches it wins; it refuses with "multiple open runs" only when more than one candidate remains. Selftest covers stale-ignored and plan-match.
- [ ] **R5** — A missing grill verdict never blocks: `codex-run.sh` prints a one-line WARN and dispatches instead of exiting 5, and `flow-status.sh` reports a missing grill verdict as a NOTE that does not count as an issue at close. Selftests that expected exit 5 / an ISSUE now expect the WARN / NOTE.
- [ ] **R6** — `flow-status.sh` section 2b (changes no lane produced) reports a NOTE, never an ISSUE: with the gates gone, inline edits and other sessions' files in the main checkout are legitimate and must not force `--force` at close. Selftests updated to match.
- [ ] **R7** — When a dispatch runs in a linked worktree, `log_start` and `log_dispatch` also append the same record to the main checkout's `.charles/dispatches.jsonl` (found via `git rev-parse --git-common-dir`), so receipts survive worktree deletion. No duplicate line when the dispatch dir is the main checkout. Selftest covers it.
- [ ] **R8** — Automatic fallback: luna and terra fall back to grok; grok falls back to luna. deepseek is no longer an automatic fallback (an explicit `--engine deepseek` still works). The `fallback_from:<engine> primary_rc:<n>` receipt is unchanged. Header comments, doctor's fallback check and selftests match.

### Docs lane (skills/, commands/, README.md, CLAUDE.md, agents/ only where they contradict the above, plus the doc-contract block of scripts/selftest.sh)

- [ ] **R9** — `skills/charles-flow/SKILL.md` is rewritten lean, at most 250 lines. Its `description:` opens with when to use it, before any architecture: e.g. "Use FIRST, before brainstorming, debugging or TDD skills, for any bug report, feature, UI pass, or build/fix-all request in a repo with a .charles.toml", and names Charles's real phrasings: "parallel agents", "sonnet fleet", "you be the orchestrator and reviewer", "fix all of these", "sdr flagged". The body's default is the lean loop: (1) read the code yourself, dispatch explore lanes only for broad unfamiliar areas, several in parallel in the background; (2) write one plan with checkable requirement IDs; (3) open the run; (4) small obvious edits the orchestrator makes itself, anything bigger goes to implement lanes, one per disjoint slice, in parallel worktrees when there are 2+; (5) one isolated review: at most 2 rounds, round 2 only re-checks round 1's Critical/Required findings, a GAPS verdict that only asks for tests becomes a DEFERRED item, a third round only for money, auth/security or data-loss changes; (6) green, sign-off, close. Grill only for money, auth/security, migrations/destructive changes, 10+ requirements, or when the user asks. Brainstorm only when the ask is genuinely open and the user is present. Two parallel reviewers only for security- or concurrency-sensitive work. Removes: the mandatory brainstorm and explore fleet, the four-part ground-truth gate (keep "baseline green before changing"), per-phase proof pasting (record phases at implement, review, green), "the review agent is the only subagent", and every reference to the removed gates and the deepseek fallback. Keeps every contract `scripts/selftest.sh` asserts on this file (work-kind selector table with UI as a router, requirement-bullet syntax, `run_in_background: true`), the omp orchestration rules in condensed form, and the fallback-to-inline ban for failed lanes.
- [ ] **R10** — `commands/feature.md`, `commands/debug.md`, `commands/polish.md` and `commands/fast-flow.md` run the lean loop and say only what differs (debug: reproduce and confirm the cause from source first; polish: one explore pass for gaps first; feature: plan; fast-flow: the lean loop on a small ask). `ui`, `release`, `ops`, `resolve`, `status`, `doctor`, `engine`, `init` change only where they mention removed behaviour.
- [ ] **R11** — `skills/grill-rounds/SKILL.md` description drops the user trigger phrases ("grill the plan", "stress-test this", "grill-rounds") and says it is invoked by charles-flow for risky plans; user requests to grill a plan belong to `lg-dev:lg-grill`.
- [ ] **R12** — `README.md` and this repo's `CLAUDE.md` no longer describe the inline-edit thresholds or subagent gate, list the remaining hooks, and state the new fallback order. `agents/*.md` change only where they contradict R1-R11.
